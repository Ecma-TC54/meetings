## 4 CycloneDX Promotions

Steve Springett (OWASP) described the current pending changes, while noting that these do not have urgency to be ready for December in case of time overrun.

### 4.1 Inventory refactor and definitions registry

Stand-out details for the committee are that this is a big structural change for the specification itself, but a rather small change in regard to functionality. It provides predefined objects in the spec and internal references. It also introduces a multiproduct inventory.

The committee had consensus to merge this change.

### 4.2 Formulation environmentVars as system-independent key-value

This is a very small change clarifying how environment variables are kept in relation to formulation.

The committee had consensus to merge this change.

### 4.3 AI Model improvements

This change is intended to provide intentional support for AI Models, as opposed to the MVP version of the feature which was not particularly bespoke for the needs of AI.

The committee had consensus to merge this change.

### 4.4 Pre-Defined perspectives

The primary normative change here is that it allows for defining how (and by whom) a perspective has been authored, and allows it to be versioned. Examples of expected uses include authorities such as CISA minimum elements, BSI minimum elements, CRA SBOM EWG recommendations, etc.

The committee had consensus to merge this change.

### 4.5 TM Library parity

OWASP’s Threat Model library made minor changes to blueprints and minor changes to threats. This change aligns CycloneDX with those modifications. Jordan Harband (Socket) requested a deeper explanation of what the benefit is of freezing when a breaking change would require a version change regardless. Steve provided the example of a model tied to a business process that exists in a given point in time, or an overall network architecture—concepts that may be blueprinted but might not be something that has a specific version applied. \`frozen\` would be used to indicate the read-only nature of that blueprint.

The committee had consensus to merge this change.

### 4.6 Rename bom-ref to refId

This change is another fairly large PR for a much smaller functional change. The intent is to remove “bom” from the identifier key due to the fact that CycloneDX 2.0 is a broader tool than just bill of materials. This is one of the few breaking changes from CycloneDX 1.7.

The committee had consensus to merge this change.

### 4.7 EPSS

Due to the fact that CycloneDX is now an API format instead of a file format, it makes sense to add EPSS. Previously it was not logical because of how frequently EPSS can change.

The committee had consensus to merge this change.

### 4.8 RDX risk alignment and safety addition

RDX comes from the committee’s work with the [Automotive Security Research Group](https://asrg.io/), and is a method of communicating risk. By aligning CycloneDX’s implementation of [RDX](https://github.com/ASRG/rdx) as closely as possible to the preexisting ideas from ASRG, ASRG has been able to abandon their work and transition entirely to using CycloneDX.

The committee had consensus to merge this change.
